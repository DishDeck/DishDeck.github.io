# DishDeck Developer Guide

Technical deep-dive into the architecture, design, and patterns used in DishDeck.

## Architecture overview

DishDeck is a fully client-side single-page app (SPA) with no backend or build step:

```
Browser
  ↓
Load index.html (root shell)
  ↓
app.js: boot() sequence
  ├─ loadTenants() → config/tenants.json
  ├─ resolveTenantId() → determine which restaurant to show
  ├─ bootConfig() → load brand.json/yaml, merge with defaults
  ├─ applyTheme() → set CSS custom properties for skin/mode
  ├─ loadMenu() → fetch menu.json or Google Sheet CSV
  ├─ renderShell() → paint header/footer/nav/menu grid
  └─ Listen for interactions (search, filters, clicks)
```

## File structure

### Root entry points

- **index.html** — Shell page (no content); app.js populates it at runtime
- **admin.html** — Menu editor (inline spreadsheet-like grid)
- **board.html** — Printable specials board (daily display or PDF)
- **qr.html** — QR code generator

All shell pages are identical. The actual content is generated by JS based on the chosen restaurant.

## Tenant resolution

When the app loads, `resolveTenantId(registry)` checks, in order:

1. `?r=<id>` — URL query parameter
2. `#/<id>` — URL hash
3. **First path segment** — e.g., `/nova-table/index.html` → `nova-table` (enables clean URLs)
4. `hosts` map in `config/tenants.json` — match current hostname
5. `default` in `config/tenants.json` — fallback

```javascript
const resolved = resolveTenantId(registry);
// { id: 'akshaya-patra', via: 'default' }
```

This allows the same shell page (`index.html`, `admin.html`) to serve multiple restaurants without per-restaurant copies.

## Config layering

Brand config is built as a series of merges (later wins):

```
DEFAULTS (in config.js)
  ↓ (merge)
config/tenants.json defaults
  ↓ (merge)
restaurants/<id>/brand.json (or brand.yaml)
  ↓ (merge)
config/runtime.json per-restaurant overrides
  ↓ (merge)
URL query params (?accent=...)
  ↓
Final brand object in memory
```

See `deepMerge()` in config.js.

## Data flow: menu loading

```
app.js: boot()
  ↓
data.js: loadMenu(brand)
  ├─ Check browser cache
  ├─ Determine source (json/sheet/csv from brand.data)
  ├─ Fetch from URL or local menu.json
  ├─ Parse (JSON, CSV, or Google Sheets CSV export)
  ├─ normalise() → convert to uniform dish shape
  ├─ Cache in localStorage + state.data
  └─ Return { items, categories, specials, soldOut, offMenu }
  
app.js: renderMenu(data)
  ├─ Disconnect old IntersectionObserver (video previews)
  ├─ Build category chips from data.categories
  ├─ Build dish grid from data.items
  ├─ Create new IntersectionObserver for video lazy-loading
  └─ Paint to DOM
```

If the source is unreachable, `loadMenu()` falls back to the cached version and shows a "showing cached menu" notice.

## Dish shape (normalised)

Every dish, from every source, is normalised to this shape:

```javascript
{
  id: string,
  category: string,
  name: string,
  desc: string,
  price: number,
  image: string | null,
  video: string | null,
  tags: string[],
  spice: number,
  status: 'on' | 'off' | 'soldout',
  special: boolean,
  specialPrice: number | null,
  variants: Array<{ name, price }> | null,
}
```

### CSV → normalised

`csvToObjects()` in util.js converts CSV rows to objects by matching column headers (case-insensitive, spelling-tolerant via `pick()`). Then `normaliseItem()` in data.js coerces each field to the right type and fills in defaults.

### Google Sheets → normalised

Sheet CSV export is fetched via a public URL (no API key), parsed as CSV, then normalised the same way.

### menu.json → normalised

JSON is already structured; `normaliseItem()` just coerces types and defaults.

## Rendering: search & filtering

```
user types in search box
  ↓
app.js: state.query = input value
  ↓
matchesQuery(item, query)
  ├─ Split query into words
  ├─ For each word, check:
  │   ├─ item.name (substring, case-insensitive)
  │   ├─ item.desc
  │   ├─ item.category
  │   ├─ item.tags (any tag contains the word)
  │   └─ AND all words must match (no OR)
  ├─ Return true only if all words match (in any order)
  └─ (search ignores category chip filter; always searches whole menu)

renderMenu()
  ├─ Filter items by query + category
  ├─ Sort by category, then by order in menu
  ├─ Build dish cards for each item
  └─ Paint to grid
```

Multi-word search: `"spicy chicken"` matches "Spicy Miso Chicken" because both `spicy` and `chicken` appear in the name.

## Video handling

### Lazy loading

```
IntersectionObserver(entries => {
  for (entry of entries) {
    if (entry.isIntersecting) {
      // Video scrolled into view
      video.src = data.video  // Fetch starts here (not before)
      video.muted = true      // Must be property, not attribute
      video.loop = true
      video.play()            // Start muted loop
    } else {
      // Video scrolled out of view
      video.pause()           // Stop playback
      video.src = ''          // Clear src to stop fetching
    }
  }
}, { threshold: 0.1 })
```

The observer is created fresh on every `renderMenu()` call. Old observers are disconnected to prevent memory leaks (they would keep watching detached DOM nodes).

### Autoplay policy

Browsers block autoplay with sound; the site works around this:

1. **Preview card:** Muted, looping — browsers allow this
2. **Full playback (detail sheet):** User click → unmute and play with sound

### Reduced motion & data saver

If `prefers-reduced-motion` is active or `navigator.connection.saveData` is true:
- No video preview (static poster image instead)
- Video still clickable to play on demand

```javascript
function wantsAutoplayPreview() {
  return !matchMedia('(prefers-reduced-motion: reduce)').matches
    && !navigator.connection?.saveData;
}
```

## Theme system

### Token structure

`theme.css` defines every colour/spacing/font as a CSS custom property. Tokens are redefined per skin and mode:

```css
:root {
  /* Base tokens (light mode) */
  --bg: #fafafa;
  --accent: #e0a63c;
  --font-display: Georgia, serif;
}

:root[data-skin="futuristic"] {
  /* Futuristic overrides */
  --font-display: 'Space Mono', monospace;
}

@media (prefers-color-scheme: dark) {
  :root:not([data-theme="light"]) {
    /* Dark mode overrides */
    --bg: #121212;
  }
}

:root[data-theme="dark"] {
  /* Explicit dark mode (user toggled) */
  --bg: #121212;
}
```

### Applying theme

`theme.js: applyTheme()`:

```javascript
applyTheme(brand) {
  // Set skin
  document.documentElement.dataset.skin = brand.theme.skin;
  
  // Set colors
  document.documentElement.style.setProperty('--accent', brand.theme.accent);
  
  // Load fonts
  if (brand.theme.fontDisplay) {
    fetchFont(brand.theme.fontDisplay);
  }
  
  // Set initial mode (auto = follow OS, or explicit dark/light)
  resolveMode(brand.theme.mode);
}
```

### Mode toggle

`toggleMode()` cycles through `auto` → `dark` → `light` → `auto`:

```javascript
function toggleMode() {
  const modes = ['auto', 'dark', 'light'];
  const current = localStorage.getItem('mode') || 'auto';
  const next = modes[(modes.indexOf(current) + 1) % modes.length];
  localStorage.setItem('mode', next);
  location.reload();  // Simple: just reload
}
```

## Admin editor (admin.js)

The admin grid is a fully editable table that mirrors the menu structure:

1. **Load:** Fetch menu (same as storefront)
2. **Display:** Build an HTML table with inputs for each cell
3. **Edit:** User types prices/status/tags directly in cells
4. **Export:** User clicks one of:
   - **Download menu.json** → trigger file download
   - **Copy CSV** → copy table as CSV to clipboard (paste into Sheet)

No backend — the editor never writes anywhere. All "saves" are downloads/copies that the user commits or pastes manually.

## QR generation (qr.js)

QR codes are generated via a free public API at request time (no bundled library):

```javascript
function qrImageUrl(text, size = 300) {
  const encoded = encodeURIComponent(text);
  return `https://api.qrserver.com/v1/create-qr-code/?size=${size}x${size}&data=${encoded}`;
}
```

Why not bundle a library? The storefront's JS stays smaller for visitors who don't need QR codes. The API is fast, reliable, and requires no key. If offline QR generation is needed, swap this for a bundled library like `qrcode.js`.

## Styling strategy

**No restaurant-specific CSS.** Every page is styled from:
1. `theme.css` — tokens per skin/mode
2. `app.css` (or `admin.css`, `qr.css`) — component layout

To add a new skin:
1. Add a new `[data-skin="myname"]` block to `theme.css` with custom token overrides
2. Set `theme.skin: "myname"` in the restaurant's `brand.json`
3. No CSS file is needed

## Responsive breakpoints

```css
@media (max-width: 900px) { /* Hero grid: 1 column */ }
@media (max-width: 640px) { /* Mobile: search/category full width */ }
@media (max-width: 480px) { /* Small phone: more aggressive layout */ }
```

Mobile-first principles:
- Base styles assume small screens
- Desktop breakpoints layer enhancements
- Touch targets are 44px minimum
- Text is readable without zoom

## Performance notes

- **Zero JavaScript frameworks** — vanilla DOM manipulation
- **No CSS-in-JS** — pure stylesheets
- **Lazy video loading** — videos only fetch when scrolled into view
- **LocalStorage caching** — menu cached per device, survives offline
- **Auto-refresh polling** — 2-minute interval (configurable)
- **No build step** — source = deployment (deploy instantly)

**Bundle size:** The app JS (~10KB gzipped) includes HTML generation, search, video handling, theme switching, and YAML parsing — zero dependencies.

## Common customizations

### Add a new skin

1. Add to `theme.css`:

```css
[data-skin="myskin"] {
  --bg: ...;
  --accent: ...;
  --font-display: ...;
  /* etc. */
}
```

2. Add to `restaurants/<id>/brand.json`:

```json
"theme": { "skin": "myskin", "accent": "#...", ... }
```

### Add a custom field to dishes

1. Add to `menu.json`:

```json
{ "name": "...", "prep_time_mins": 15, ... }
```

2. In `app.js`, update `dishCard()` to display it:

```javascript
prep_time_mins ? h('span.detail', {}, `${it.prep_time_mins}m`) : null,
```

### Add a new page

1. Create `newpage.html` (shell; content filled by JS)
2. Create `assets/js/newpage.js` with `boot()` function
3. In `newpage.html`, import it: `<script type="module" src="/assets/js/newpage.js"></script>`

### Change auto-refresh interval

In `data.js`, modify `loadMenu()`:

```javascript
const POLL_INTERVAL = 120000; // 2 minutes (milliseconds)
```

### Add authentication to admin.html

Admin.html currently has no auth — anyone who can reach it can download/export the menu. To gate it:

1. Add a password prompt at the top of `admin.js: boot()`
2. Or deploy to a private URL (e.g., behind a VPN or CloudFlare Access)
3. Or use GitHub's built-in branch protection to gate who can edit the Sheet
